# Domain Docs

本仓库的领域文档如何被工程技能消费。

## 探索前先读

- 仓库根 `.GLOSSARY.md`（或存在 `GLOSSARY-MAP.md` 时按其指向按上下文读）
- `docs/adr/`：读将要工作的区域相关的 ADR

这些文件若不存在，静默继续，不主动建议创建（由 `/domain-modeling` 在有需要时懒创建）。

## 文件结构

单上下文（本仓库）：

```
/
├── GLOSSARY.md
├── docs/adr/
│   └── 0001-*.md
└── src/
```

## 使用词汇表的语言

输出为领域概念命名（ticket 标题、重构建议、假设、测试名）时，使用 `GLOSSARY.md` 的定义，不偏离其明确避免的同义词。若所需概念不在词汇表，说明要么在发明项目不用的语言（重新考虑），要么是真实缺口（记给 `/domain-modeling`）。

## 标注 ADR 冲突

若输出与既有 ADR 冲突，显式提出而非静默覆盖。
